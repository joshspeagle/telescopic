# M1 and M2 review: couplings, targets, initial distributions, first kernels

**Diff:** 2ac3568..5b39221 (couplings, `_linalg`, `Target`, initial distributions, the
kernel base, RandomWalk, Independence, Mixture, and their tests), about 1,600 added
lines touching numerics and the public API: four `/simplify` reviewers, one per angle.
The `/code-review` pass runs on M0 to M3 together (DECISIONS #3).

## Outcome

Two bugs and one latent bias were found, all by more than one reviewer:

- `State.take` returned views for slices, so `Mixture.step` and `coupled_step` wrote into
  their callers' states, and two Mixture tests compared arrays with themselves. `take`
  now always copies; a new test checks that no kernel modifies its inputs.
- Kernels evaluated proposals without gradients, and `select` and `put` skipped them, so a
  gradient kernel mixed with RandomWalk would read stale gradients (the altitude reviewer
  measured z = +20 on E[x²] for MALA mixed with RWMH). Kernels now evaluate what their
  input states carry, and a new test checks that carried gradients are valid at every
  new position. Spec §5.1 (States) states the rule.
- A coupling test passed only through rounding at an exact tie (u = eta p/q); its
  uniform was moved off the tie.

Other changes:

- One covariance check, `_linalg.covariance`, for RandomWalk, MultivariateT and
  `initial.Normal`. `Normal` had accepted an asymmetric matrix (sampling its lower
  triangle) and raised a bare `LinAlgError` for an indefinite one.
- One draw protocol, `rvs(random_state=generator)`, for initial distributions (frozen
  SciPy ones, the helpers, callables), so `as_initial` no longer matches objects by a
  method named `sample`. The `Initial` protocol and `_Frozen` are gone; `Distribution`
  lives in `_types.py` with the array aliases, which had been defined in four modules.
- `Target` no longer judges gradients: a non-finite gradient at a finite density raises at
  initial states (`Kernel.init_state`), and gradient kernels will reject such proposals
  (spec R-INPUT-1). The NaN and `+inf` check takes one reduction. A point-by-point
  function returning the wrong shape now raises the named error instead of being reshaped.
- `evaluate_pair` builds Y's state with one gather; IMH computes its proposal density
  once per step; `discrete_maximal` uses `scipy.special.softmax`; `maximal` derives
  `identical` from the draw count; `_Gaussian` whitens with the kernel's inverse factor.
- Tests: binomial tests replace hand-written 5-sigma bounds; `P_MIN` and the Gaussian
  log-density live in `tests/references.py`; one kernel factory takes a covariance, and
  the three-dimensional marginal test uses a dense one (catching a transposed factor);
  the discrete-coupling tests became one that catches six normalisation mutants; an
  `@example` replaces the equal-means test.

## Findings not adopted

- Efficiency: a special case for a mixture whose rows all choose one component (−14% at
  one lane). It is a special case on a general path; revisit if HMC's meeting step is
  built on `Mixture` (M6).
- Efficiency: the one-lane overhead target (40 µs per pair-step) is missed by about 2× in
  the kernel alone. The target is restated with the engine's measurements in the M3
  report.
- Simplification: delete `is_tuned` (no caller at M2). The sampler and the kernels'
  `tune` methods of M5 use it.
- Altitude: `step` returning acceptance probabilities instead of flags, for tuning by
  dual averaging. Deferred to M6, which adds dual averaging; the M5 adaptive Metropolis
  pilot runs its own vectorised step and does not rebuild kernels.
- Altitude: shipping the initial distribution and the kernel to workers, and per-task
  evaluation counts: recorded in spec §6.4 for M7; the counts move into the engine with
  the M3 fixes.
- Reuse: `couplings._log_uniform` stays: it reads the row's parent generator inside the
  rejection loop, which `Draws.log_uniform` cannot.
